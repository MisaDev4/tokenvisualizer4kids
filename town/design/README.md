# Design record

The written thinking behind Token Town, rescued from session scratchpads before they were
cleaned up. These are **historical design studies**, not specifications of the current code:
where a document and the source disagree, the source is right.

The binding, current documents live one level up: `../AESTHETIC.md` (what the town is
supposed to look like), `../REDESIGN.md` (v2) and `../REDESIGN-V3.md` (v3).

## v4 — the photographic pass

| file | what it is |
|---|---|
| `v4-BACKLOG.md` | the binding v4 plan: pitch, ranked backlog, wave/ownership schedule, pinned module contracts, risk register, copy gate, definition of done |
| `v4-WIRING.md` | the 844-line integration recipe the wiring stages followed |
| `v4-bench-baseline.md` | the perf baseline a bench regression is measured against |

Eight parallel design studies fed that plan: `v4-lookdev` (the picture),
`v4-interaction` (camera + deed cards), `v4-lifesim` (villagers), `v4-history` (chronicle),
`v4-weather`, `v4-progression` (badges), `v4-datadepth` (what the feed may say) and
`v4-engine` (LOD, budgets, epochs).
